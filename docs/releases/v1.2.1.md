# Geza v1.2.1

Behebt den Abbruch einer Demo-Installation mit „POSTGRES_PASSWORD is missing a value“, wenn bereits eine unvollständige `.env.demo` vorhanden ist.

- Fehlende und leere Pflichtwerte werden ergänzt; vorhandene Zugangsdaten, Domain, Port und weitere Einstellungen bleiben erhalten.
- Setup-Meldungen nennen korrekt `.env` oder `.env.demo`.
- Widersprüchliche Angaben zu Modus und Konfigurationsdatei werden ohne Änderung abgewiesen.
- Der Demo-Start zeigt nicht zusätzlich die Produktionsadresse an.

Auf dem Server `git pull --ff-only` und anschließend `sh setup.sh demo` ausführen. Bestehende Konfigurationen und Datenbankvolumes nicht löschen. Bei einer schon früher eingerichteten Datenbank muss ein verlorenes Datenbankpasswort aus der bisherigen Konfiguration wiederhergestellt werden.

Geprüft mit 26 Unit-/Regressionstests, Typprüfung sowie Node 22 im Docker-Container und anschließender Compose-Konfigurationsprüfung einer zunächst unvollständigen `.env.demo`.
