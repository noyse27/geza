# Geza v1.2.0

Geza kann jetzt als öffentliche, getrennte Demo auf der eigenen Website angeboten werden. Das Release enthält außerdem die seit v1.1.1 hinzugekommenen Funktionen für Serverumzüge und Plex.

## Öffentliche Demo

- Installation mit `./setup.ps1 -Mode demo` oder `sh setup.sh demo`, standardmäßig auf Port 3081. Produktion bleibt der Standard ohne zusätzliches Argument.
- Eigene Konfiguration und Datenbank; automatischer Import von `demo.geza` mit zwölf erfundenen Medieneinträgen, Bewertungen, Reviews und drei offenen Scrobbles. Login: **admin / admin**.
- Reviews, Bewertungen und Nachpflege ausprobieren; der Worker stellt standardmäßig alle 60 Minuten die Ausgangsdaten wieder her und beendet bestehende Anmeldungen.
- Trakt-ZIPs liefern ausschließlich eine Vorschau. Geza-Wiederherstellung, externe Providerzugriffe und Änderungen an Zugangsdaten sind in der Demo gesperrt.
- Website-Einbettung per iframe mit expliziter Domainfreigabe; sichtbarer Demohinweis und keine Suchmaschinenindexierung.

Alle Besucher teilen dieselbe Demo. Änderungen sind vorübergehend. Demo und Produktion müssen getrennte Datenbanken verwenden. Die Demodatei allein aktiviert keinen Demomodus; ihr öffentlicher Wiederherstellungsschlüssel besteht aus 64 Nullen.

## Weitere Neuerungen seit v1.1.1

- Vollständiger Serverumzug über eine `.geza`-Datei mit verschlüsselten Konten und Zugangsdaten, Vorschau und auswählbarer Übernahme. Wiederherstellung über den Erststart-Assistenten oder `scripts/restore.ts` mit Fortschrittsausgaben.
- Scrobble-Zuordnung fortsetzen und aktive Plex-Wiedergaben auf Home anzeigen.
- Now Playing ergänzt fehlende Plex-IDs für passende Katalog-Cover und verwendet bei Bedarf einen geschützten Plex-Poster-Fallback ausschließlich im privaten Wiedergabeblock.
- Verbesserte Filmdienst-Suche mit zuverlässigerem Titel- und Jahresabgleich.
- Korrigierter Image-Build für den Worker sowie aktualisierte Hinweise zur erforderlichen `PUBLIC_URL` bei Domainzugriffen.

## Aktualisieren und prüfen

Vor einem produktiven Update eine Sicherung erstellen, den Quellcode aktualisieren und `docker compose up --build -d` ausführen. Migrationen werden automatisch ausgeführt. Für Serverumzüge beide Installationen auf dieselbe Version bringen.

Die README und `docs/demo.md` enthalten Installation und Hosting. Die Demo wurde mit Docker und PostgreSQL 16 einschließlich Login, unveränderter Datenbank nach Trakt-Vorschau, Importsperren, Uploadlimit, Origin-Prüfung, Reviews, Scrobbles und tatsächlichem Worker-Reset geprüft. Automatisierte Tests prüfen zusätzlich den Schutz bestehender Daten und den Moduswechsel.
